# Baseball AI Detector

YOLO11n Pose로 사람 박스, COCO 17개 관절, 스켈레톤 및 타자 후보의 2D 관절 각도를 표시합니다.
학습이나 라벨링은 필요하지 않습니다. 웹/서버/DB/영상 비교 기능은 없습니다.

## 설치 및 실행 (Windows PowerShell)

Python 3.11 또는 3.12를 권장합니다. 공식 Python 설치 시 Tkinter(tcl/tk)와 PATH 옵션을 포함하세요.

```powershell
cd C:\Users\nyzer\OneDrive\Desktop\vision3\baseball-ai
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\Activate.ps1
python main.py
```

PowerShell에서 활성화가 차단되면 `.\.venv\Scripts\python.exe main.py`로 직접 실행하세요.
이미 가상환경을 준비했다면 환경 생성 단계는 생략하세요.
Tkinter는 Python에 포함되며 pip로 설치하지 않습니다.
PyTorch/torchvision은 Ultralytics 의존성이며 GPU 없이 CPU로 실행합니다.

파일 선택창에서 MP4, AVI 등 영상을 선택하세요. 취소하면 정상 종료합니다.
첫 실행 시 `models/yolo11n-pose.pt`가 없으면 Ultralytics 공식 기능으로 다운로드하므로 인터넷이 필요합니다.
이후에는 로컬 모델을 사용합니다. 다운로드 실패 시 터미널의 원인과 연결/권한을 확인하세요.

## 화면 및 조작

창 제목은 `Baseball AI Detector`입니다. 초록색 사람 박스, 사람 신뢰도(0~1),
주황색 관절 점, 청록색 연결선, 실제 처리 FPS와 사람 수를 표시합니다.
선택된 타자는 두꺼운 박스와 `BATTER` 라벨로 표시합니다.
첫 프레임 FPS는 0이며 이후 직전 프레임의 처리/대기 시간을 반영합니다.
사람 신뢰도 기준은 `CONFIDENCE = 0.25`, 관절 기준은 `KEYPOINT_CONFIDENCE = 0.5`입니다.
관절 신뢰도가 낮거나 좌표가 유효하지 않으면 점과 연결선을 그리지 않고 해당 각도를 `측정 불가`로 표시합니다.
영상 비율을 유지하며 최대 1100×720으로 축소하고, 옆에 한글 각도 패널을 배치합니다.
한글 표시는 Pillow와 Windows 맑은 고딕을 사용합니다.
CPU 성능에 따라 원본 영상보다 느리게 재생될 수 있으며 모든 프레임을 순서대로 분석합니다.

최초 타자 후보는 박스 크기, 중앙 위치와 관절 신뢰도로 선택합니다. 타자를 의미적으로 구분하는 모델은 아닙니다.
이후 박스 겹침과 중심 거리로 연결하므로 교차/가림/빠른 이동에서 다른 사람과 혼동할 수 있습니다.
잘못 선택되면 원하는 사람 박스 안을 클릭하세요. 일시정지 후 선택하면 확인하기 쉽습니다.
겹치는 박스를 클릭하면 작은 박스를 우선합니다. 대상을 잃으면 이전 각도를 재사용하지 않습니다.

OpenCV 영상 창을 클릭해 키 입력 초점을 맞추세요.

| 키 | 동작 |
| --- | --- |
| Q | 종료 (창 닫기로도 종료) |
| Space | 일시정지 / 재생 |
| R | 처음부터 다시 재생 (일시정지 중에도 재생 시작) |
| S | 분석 영상 저장 시작 / 중지 |
| C | 현재까지 분석한 데이터를 새 CSV로 저장 |
| 마우스 왼쪽 클릭 | 타자 후보 변경 |

영상 끝에서는 저장 중인 영상을 마무리하고 마지막 화면을 유지합니다. C로 CSV를 저장하거나 R로 재생, Q로 종료하세요.
R은 메모리의 분석 기록과 타자 선택을 초기화하고 녹화를 종료합니다. 필요한 CSV는 R 전에 저장하세요.
중간 프레임 읽기에 실패하면 오류를 안내하고 종료합니다.
일부 코덱은 영상 길이 정보를 제공하지 않으므로 EOF와 읽기 오류를 정확히 구분할 수 없습니다.
영상이 열리지 않으면 파일 손상 여부를 확인하거나 MP4(H.264)로 변환해 보세요.
화면 출력에는 GUI를 지원하는 `opencv-python`이 필요합니다(`opencv-python-headless` 제외).

## 각도와 선택적 저장

팔꿈치·무릎은 가운데 관절을 꼭짓점으로 하는 0~180도 각도입니다.
상체 기울기는 골반 중점→어깨 중점의 위쪽 수직 기준 각도이며, 화면 오른쪽 기울기가 양수입니다.
어깨선과 골반선은 선수의 왼쪽 관절→오른쪽 관절 방향입니다.
영상 오른쪽이 0도, 아래쪽이 +90도인 -180~180도 방향이며, 3D 회전이나 회전량이 아닙니다.
좌우 관절 이름은 선수의 해부학적 좌우로 화면 좌우와 다를 수 있습니다.

저장 키를 누르지 않으면 `outputs/`나 결과 파일을 만들지 않습니다.
S를 누르면 현재 화면부터 MP4(mp4v)로 기록하며 중지/영상 끝/종료 시 파일을 마무리합니다.
원본 FPS로 저장하므로 CPU 분석이 느려도 저장 영상은 원본 시간 속도로 재생됩니다.
일시정지 중에는 중복 프레임을 기록하지 않고 오디오도 저장하지 않습니다.

C는 이번 재생에서 분석한 모든 프레임의 **선택된 타자 한 명** 데이터를 UTF-8 BOM CSV로 저장합니다.
프레임 번호(1부터), 영상 시간(초), 선택 구간 target_id, 사람 신뢰도,
17개 관절의 원본 픽셀 x/y/신뢰도, 7개 각도를 포함합니다.
영상 시간이 제공되지 않으면 프레임 번호/FPS로 추정합니다. 가변 FPS 영상에서는 추정 오차가 있을 수 있습니다.
유효하지 않은 좌표와 각도는 빈 칸으로 기록하며, 낮은 관절 신뢰도는 그대로 남깁니다.
같은 프레임에서 타자를 다시 선택하면 해당 행을 갱신하고, 이후 프레임부터 새 선택 구간 번호를 사용합니다.
과거 프레임을 새 타자로 다시 분석하지 않습니다. 사람 미검출 프레임도 빈 측정값으로 기록합니다.
C를 다시 누르면 그 시점까지의 전체 스냅샷을 별도 파일로 저장합니다.
좌표 데이터는 저장 전까지 메모리에 두므로 긴 영상에서는 메모리 사용량이 늘어납니다.

빠른 동작과 가림/시점 때문에 추정 오류가 생길 수 있습니다. 이 값은 영상상의 2D 각도이며
실제 3D 관절 회전, 배트 위치, 임팩트, 체중 이동량이나 타격 능력을 측정하지 않습니다.

## 프로젝트 구조

```text
baseball-ai/
├── main.py
├── pose_utils.py
├── test_pose_utils.py
├── requirements.txt
├── README.md
└── models/
    └── yolo11n-pose.pt  # 없으면 첫 실행 시 공식 다운로드
```

기존 `models/yolo11n.pt`는 보존하며 새 포즈 분석에서는 사용하지 않습니다.
`.venv/`는 실행 환경이며 `outputs/`는 사용자가 저장을 선택한 경우에만 생성됩니다.

## 검증 상태

각도 단위 테스트 실행:

```powershell
python -m unittest -v test_pose_utils
```

Python 3.12에서 공식 Pose 모델 로딩, CPU 빈 이미지 추론과 패키지 내장 일반 사진의 양성 포즈 추론,
한글 패널 렌더링, Tkinter/OpenCV 창 초기화를 확인했습니다.
각도 단위 테스트 10개를 통과했습니다. 내장 일반 사진을 임시 동영상으로 인코딩해 영상 읽기,
분석 MP4 저장 후 재디코딩, CSV 저장 및 영상 끝 처리를 검증했습니다.
Q/Space/R/S/C와 클릭은 자동 입력으로 검증했고 테스트용 파일은 임시 폴더에서 정리했습니다.
실제 야구 타격 영상은 제공되지 않았으므로 선수 동작 추적 정확도와 사용자의 실제 키/마우스 조작은 직접 확인해야 합니다.

모델 및 API 참고: [Ultralytics YOLO11 공식 문서](https://docs.ultralytics.com/models/yolo11/).
